Описание схемы «ЛОГИЧЕСКАЯ АРХИТЕКТУРА СППР»

Документ описывает структуру Системы Поддержки Принятия Решений (СППР) для управления персоналом. Схема отражает полный путь обработки данных — от их сбора до выдачи готовых рекомендаций для лиц, принимающих решения. Компоненты схемы расположены последовательно (слева направо) и образуют единый рабочий процесс.

1. Источники данных

На начальном этапе информация поступает из следующих источников:

  • внешние данные — резюме кандидатов, информация из социальных сетей;
  • внутренние OLTP‑системы — данные о результатах тестирования персонала;
  • рыночные отчёты — сведения о текущей ситуации на рынке труда (например, периоды роста или кризиса);
  • мнение экспертов — субъективные оценки и рекомендации специалистов.

2. Хранилище данных (DWH)

Все собранные данные направляются в центральное Хранилище данных (Data Warehouse, DWH). На этом этапе выполняется:

  • сбор информации из разнородных источников;
  • очистка данных от ошибок, дубликатов и неточностей;
  • структурированное хранение унифицированных данных.

3. Витрины данных

Из общего хранилища данные распределяются по витринам — специализированным разделам, ориентированным на решение конкретных задач управления персоналом:

  • отбор кандидатов — подготовка данных для оценки претендентов на вакансии;
  • стратегическое планирование кадров — формирование прогнозов и планов по развитию персонала;
  • распределение ресурсов по проектам — оптимизация загрузки сотрудников в текущих и будущих проектах.

4. Методы анализа

Для каждой витрины применяются специализированные аналитические методы:

Витрина «Отбор кандидатов»:

  • сложное дерево решений — для классификации кандидатов по критериям соответствия;
  • нечёткое множество — для работы с размытыми или субъективными оценками;
  • метод анализа иерархий — для ранжирования кандидатов по совокупности факторов.

Витрина «Стратегическое планирование кадров»:

  • игры с природой — для моделирования сценариев в условиях неопределённости;
  • многокритериальная оптимизация — для поиска баланса между целями развития, бюджетом и ресурсами;
  • метод анализа иерархий — для структурирования стратегических приоритетов.

Витрина «Распределение ресурсов по проектам»:

  • многокритериальная оптимизация — для оптимального распределения задач между сотрудниками;
  • парные игры — для анализа взаимодействий между участниками проектов;
  • игры с природой — для учёта внешних факторов (сроки, риски, изменения требований).

5. Результаты и пользователи

После обработки данных система формирует итоговые результаты:

  • ранжированный список кандидатов с оценкой их соответствия вакансиям;
  • рекомендации по действиям («Принять», «Отклонить», «Условно принять»);
  • стратегические рекомендации (например, план развития персонала на 1–3 года);
  • аналитические отчёты с детализацией по выбранным параметрам.

Результаты предоставляются следующим категориям пользователей:

  • лицо, принимающее решения (руководитель) — получает итоговые рекомендации для утверждения;
  • специалист по кадрам — использует данные для оперативного управления персоналом;
  • тестировщик / эксперт — анализирует результаты оценки кандидатов или проектов;
  • ответственный за стратегические решения — опирается на прогнозы и планы для долгосрочного планирования.

Описание схемы «ПОДСИСТЕМА ХРАНЕНИЯ И ОБРАБОТКИ ДАННЫХ»

Документ детализирует процесс хранения и обработки данных в рамках Системы Поддержки Принятия Решений (СППР). Схема организована последовательно (слева направо) и отражает этапы преобразования «сырых» данных в структурированную информацию для дальнейшего анализа.

Основной поток обработки данных

1. ETL‑процессы
Начальный этап работы с данными. Включает три последовательных действия:

  • Extract (извлечение) — сбор данных из разнородных источников;
  • Transform (преобразование) — первичная обработка и трансформация данных под требования системы;
  • Load (загрузка) — помещение подготовленных данных в центральное хранилище (DWH).

2. Очистка и интеграция данных
На этом этапе выполняется:

  • выявление и исправление ошибок в данных;
  • удаление дублирующих записей;
  • устранение несоответствий между данными из разных источников;
  • приведение всех данных к единому формату;
  • объединение информации из различных систем в единую согласованную структуру.

3. Агрегация и предобработка данных
Этап подготовки данных для аналитической обработки:

  • обобщение информации (расчёт сумм, средних значений, медиан и других статистических показателей);
  • группировка данных по заданным критериям;
  • создание производных показателей и метрик;
  • формирование наборов данных, готовых к анализу и визуализации.

4. Формы хранения данных
После обработки данные сохраняются в одной из трёх форм:

  • Физическая структура — полная копия данных размещается в центральном хранилище. Обеспечивает высокую скорость доступа и независимость от исходных систем.
  • Виртуальная структура — данные остаются в исходных системах, а хранилище предоставляет унифицированный интерфейс для их просмотра и использования. Снижает объём хранимой информации, но требует постоянного доступа к источникам.
  • Гибридная структура — комбинация физического и виртуального хранения. Критически важные данные копируются в хранилище, а второстепенные остаются в исходных системах. Позволяет сбалансировать скорость доступа и объём хранимых данных.

Подсистема метаинформации

Отдельный компонент системы, связанный со всеми этапами обработки данных. Обеспечивает корректную работу остальных модулей за счёт хранения и управления служебной информацией:

  • описание структуры данных (схемы, таблицы, поля);
  • иерархия данных (отношения между объектами, вложенность);
  • форматы хранения и представления данных;
  • правила агрегации (как и какие показатели рассчитываются);
  • график и частота обновления данных;
  • права доступа пользователей (кто и к каким данным имеет доступ).
